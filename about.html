Hibernate: an introduction

Hibernate is an object-relational mapping (ORM) framework for Java. It helps applications store and retrieve Java objects in a relational database without requiring every database operation to be written as low-level SQL.

Object-relational mapping

A relational database stores data in tables and rows, while Java programs work with objects and classes. Hibernate connects these models through mapping metadata. An entity is a Java class mapped to a database table; its fields correspond to columns and its instances correspond to rows. This mapping can be described with annotations or configuration.

Sessions and transactions

A Hibernate Session is the main interface for interacting with persistent objects. Applications use it to save, find, update, or delete entities. Database changes should be grouped in a transaction, which can be committed when all operations succeed or rolled back if a failure occurs.

Queries and database support

Hibernate Query Language (HQL) queries entities and their properties rather than database tables and columns. Hibernate translates queries into SQL for the configured database. A database dialect tells Hibernate which SQL features and syntax to use. Associations between entities are configured through their mapping.

Persistence and caching

Persistence is the process of keeping application data after a program finishes. Hibernate tracks changes to managed entities and can write those changes to the database when a transaction is committed. A first-level cache within a session can avoid repeated database reads for the same entity.

Hibernate and Spring JDBC

Both technologies help Java applications work with relational databases, but they take different approaches. Hibernate maps objects to tables and manages entity state. Spring JDBC simplifies JDBC access while leaving SQL and row-to-object mapping more directly under the developer's control. Choose the approach that fits the application's data model and desired level of abstraction.
